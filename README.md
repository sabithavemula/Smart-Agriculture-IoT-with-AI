# Smart Agriculture Using IoT Technology with AI-Based Prediction

A local software prototype that demonstrates the project described in the proposal: monitor soil moisture, temperature, humidity, light intensity and water level; predict future soil moisture with machine learning; and demonstrate an irrigation recommendation and pump-control state.

> **Prototype transparency:** No physical ESP32, sensors, relay or water pump are connected in this version. The browser runs a sensor-data simulator that sends readings automatically to the FastAPI backend. The ML model is trained on a reproducible **synthetic demonstration dataset**, not measurements from a real farm. Its reported metrics therefore describe only this synthetic dataset and must not be presented as validated agricultural accuracy.

## Features

- Five sensor readings stored in SQLite with timestamps and source labels.
- FastAPI endpoint designed for ESP32 Wi-Fi POST requests: `POST /api/esp32/readings`.
- Automatic browser-based sensor simulator for demonstrations without hardware.
- Synthetic dataset generation with a defined target: soil moisture 30 minutes later.
- Random Forest Regression training and Linear Regression baseline comparison.
- Train/test split and evaluation using MAE, RMSE and R².
- Saved model loaded by the application to predict future soil moisture from all five sensor inputs.
- Irrigation recommendation based on current and predicted moisture plus water availability.
- Software-only pump/relay state; no real electrical device is controlled.

## Requirements

- Windows 10/11
- Python 3.10 or newer (Python 3.11/3.12 recommended)
- VS Code

## Run in VS Code (Windows PowerShell)

1. Extract this ZIP.
2. Open the extracted `Smart-Agriculture-IoT-Final` folder in VS Code (`File > Open Folder`).
3. Open `Terminal > New Terminal`.
4. Create a virtual environment:

   ```powershell
   py -m venv .venv
   ```

5. Activate it:

   ```powershell
   .\.venv\Scripts\Activate.ps1
   ```

   If PowerShell blocks activation, run this once in the current terminal, then activate again:

   ```powershell
   Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
   .\.venv\Scripts\Activate.ps1
   ```

6. Install packages:

   ```powershell
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   ```

7. Generate the synthetic demonstration dataset:

   ```powershell
   python scripts/generate_dataset.py
   ```

8. Train and evaluate the ML model:

   ```powershell
   python scripts/train_model.py
   ```

9. Start the web application:

   ```powershell
   python -m uvicorn app.main:app --reload
   ```

10. Open `http://127.0.0.1:8000` in your browser. The sensor simulator starts automatically and sends a new simulated reading every 10 seconds. The dashboard refreshes the readings, prediction and pump simulation.

API documentation: `http://127.0.0.1:8000/docs`

## How the ML model works

- **Features (X):** soil moisture, temperature, humidity, light intensity and water level.
- **Target (y):** simulated soil moisture 30 minutes later.
- **Dataset:** `data/synthetic_agriculture_readings.csv`, generated by `scripts/generate_dataset.py` with a fixed random seed for reproducibility.
- **Training:** `scripts/train_model.py` uses an 80/20 train/test split. It fits a Linear Regression baseline and a Random Forest Regressor.
- **Evaluation:** MAE, RMSE and R² are saved to `models/training_metrics.json`.
- **Inference:** the API loads `models/soil_moisture_model.joblib` and predicts from each new five-feature sensor packet.

The synthetic target is generated from a simple illustrative scenario (starting moisture, heat, light, humidity, available water and random variation). It is useful for demonstrating the complete ML workflow, but it is not a scientifically validated crop/soil model. Real deployment requires calibrated sensor data collected over time, a well-defined prediction horizon and field validation.

## ESP32 integration later

When hardware is available, configure ESP32 to send an HTTP `POST` request to:

`http://<computer-LAN-IP>:8000/api/esp32/readings`

Example JSON body:

```json
{
  "soil_moisture": 42.5,
  "temperature": 29.0,
  "humidity": 64.0,
  "light": 72.0,
  "water_level": 80.0
}
```

All five values must be numeric. The computer and ESP32 must be on the same network, and the server must be reachable from the local network. For an actual pump, add an appropriately rated, isolated relay driver and hardware safety protections; do not connect a pump directly to an ESP32 GPIO pin.

## API endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/api/health` | Application/model status |
| GET | `/api/readings` | Stored readings |
| POST | `/api/esp32/readings` | Receive sensor packet from ESP32 |
| POST | `/api/demo-reading` | Generate one simulated reading |
| GET | `/api/prediction` | Latest future-moisture prediction |
| GET | `/api/status` | Irrigation and simulated pump status |
| POST | `/api/mode?enabled=true/false` | Enable/disable automatic irrigation simulation |
| GET | `/api/model-info` | Training dataset details and evaluation metrics |
